# 阶段 3b-1：共用界面 设计

日期：2026-09-07
状态：已确认，待实施
前置：阶段 3a 已完成（core-server 独立运行，GUI 是它的客户端，45 个测试全绿）

## 1. 为什么把 3b 再拆一次

3b 原本装了八样东西：构建步骤、框架选型、共用界面、Tailscale、令牌、断线重连、跨网络的
权限确认、手机适配。这比 1b 和 3a 都大，而且**混了两类风险**：前半是「写代码，跑起来看」，
后半是「安全与网络，出问题不报错」。

沿用 3a 的逻辑再拆一次：

- **3b-1（本文）：构建步骤 + 共用界面。** 仍只连 `127.0.0.1`，浏览器就在本机开。零网络安全面。
- **3b-2：远程接入。** Tailscale、令牌、断线重连、手机适配。届时界面已验证过，出问题只可能在网络部分。

## 2. 目标

**一套界面代码，Electron 与浏览器都加载它。**

达成后 `packages/desktop` 只剩「开一个窗口指向 `http://127.0.0.1:4517`」，约 25 行。

## 3. 范围

**做：**

- 用 React 重写现有 GUI 的全部功能：消息流、工具卡片、权限确认、thinking 折叠、
  费用显示、中止、系统提示
- **Markdown 渲染**（当前最明显的痛点，重写时顺带做最省事）
- **目录选择器**：服务器列目录，界面画成可点的选择器
- 删除 `preload.js` 与全部 IPC 通道

**不做**（全在 3b-2）：远程访问、鉴权、断线重连、手机适配。

**不提前拉进阶段 4 的东西**：模型切换、会话历史、会话分叉。

## 4. 架构变化

```
3a（现在）                          3b-1 之后
┌──────────────────┐               ┌────────────────────────┐
│ core-server      │               │ core-server            │
│  ws              │               │  ws + HTTP 静态文件      │  同一端口 4517
└────────┬─────────┘               └───────────┬────────────┘
         │ WebSocket                           │ WebSocket（界面直连）
┌────────▼─────────┐               ┌───────────▼────────────┐
│ Electron 主进程   │               │ 浏览器  或  Electron 窗口 │
│  WebSocket ↔ IPC │               │   React 界面（同一份代码） │
├──────────────────┤               └────────────────────────┘
│ 渲染层（手写 DOM） │
└──────────────────┘               Electron 主进程 → 只剩开窗口
```

**中继层整个消失。** 3a 里主进程之所以当中继，是因为渲染层跑不了 `.ts`；3b-1 引入构建步骤后
这个理由不存在了，界面直接连服务器——和浏览器走完全相同的路径。

## 5. 技术选型

### 5.1 React

理由是三个方向能统一：阶段 4 的 TUI 若换 Ink 就是 React；将来移动端可走 React Native；
网页与桌面本就同一套。生态最大、文档最全，遇事搜得到。

### 5.2 Vite，且不需要放行任何安装脚本

**这是选型时专门核实的一点。** 仓库从阶段 1a 起就有三个包的安装脚本未被批准
（`@google/genai`、`esbuild`、`protobufjs`），这是刻意保持的安全姿态。

Vite 8 已把 esbuild 换成 rolldown，实测其依赖链上没有 install 类生命周期脚本：

```
vite 8.2.2            无 preinstall / install / postinstall
rolldown              无
lightningcss          仅有 prepare —— 从 npm 安装依赖时不执行
                      （prepare 只在从 git 安装、或在该包自己目录里 npm install 时运行）
react 19.2.8          无
react-dom 19.2.8      无
react-markdown 10.1.0 无
@vitejs/plugin-react 6.1.1  无
```

**验收项：`npm install` 之后被拦下的安装脚本仍是原来那三个，没有变多。**
这是元数据层面的判断，安装那一刻才是最终确认。

### 5.3 Markdown 用 react-markdown

它默认**不允许原始 HTML**，且构建的是 React 节点树而不是往 DOM 里塞字符串。

阶段 1b 之所以推迟 Markdown，正是因为「模型输出用 `innerHTML` 渲染等于让模型往界面注入标记」。
`react-markdown` 从根上避开了这一点——模型输出 `<script>` 只会显示成文字。

**验收项：让模型输出一段 HTML，确认它显示为文字而非被执行。**

## 6. 协议新增

目录浏览需要两条消息，加进 `core-client/src/protocol.ts`：

```jsonc
// 客户端 → 服务器
{ "type": "list_dir", "path": "C:\\Users\\shenxichen" }

// 服务器 → 客户端
{ "type": "dir_listing", "path": "...", "parent": "...", "dirs": ["repos", "Documents"] }
```

`parent` 为上一级路径，已在根目录时为 `null`。`dirs` 只含子目录名，不含文件——选项目只关心目录。

### 6.1 为什么浏览器不能自己选目录

网页拿不到本地路径，这是刻意的安全限制。Chromium 的 `showDirectoryPicker()` 给的是一个
**目录句柄**，只能让网页自己读写那些文件，**给不出路径字符串**——而 Pi 跑在服务器上，
它需要的正是路径。

我们的架构里这件事其实更简单：**文件和 core-server 在同一台机器上**，服务器自己能列目录，
浏览器只负责把结果画出来。这是服务器端开发工具的标准做法，桌面与网页共用一条路径。

### 6.2 安全说明

「能列目录」意味着连上来的人能浏览文件系统。但**该服务本就能执行任意命令**（`ls` 一下什么都
看得到），因此列目录没有增加任何新能力。真正的防线是 3b-2 的 Tailscale + 令牌，而不是少开
这个接口。

## 7. 构建与加载

```
写界面时：  vite dev server，浏览器开 5173，有热更新
验证时：    npm run build → 产物进 packages/web/dist
            core-server 提供静态文件 → Electron 与浏览器都看 4517
```

Electron 始终加载构建产物，不搞两套加载逻辑。热更新只在浏览器里用——先在浏览器写界面、
再到 Electron 验证，是这一阶段的开发节奏。

## 8. 依赖形状

```
web         → @cinba/core-client   （RemoteSession、ViewAction、Snapshot 等类型）
            → react / react-dom / react-markdown
            → vite / @vitejs/plugin-react（构建期）

desktop     → 无运行时依赖（只剩 electron 与开窗口的代码）

core-server → 不变，另加静态文件服务（用 Node 内置 http，不引入框架）

core-client → 保持零依赖
```

`core-client` 被编译进浏览器包，这正是它从第一天起坚持零依赖换来的——**它能整个搬进浏览器，
是因为它什么都不依赖，且唯一一处 `node:child_process` 是纯类型引用，编译时就擦掉了。**

## 9. 测试策略

| 层 | 手段 |
|---|---|
| `protocol.ts` 新增的 `list_dir` 校验 | `node --test`，纯函数 |
| React 组件 | 不引入测试框架，靠手工验收 |
| 现有 45 个测试 | 必须保持全绿 |

不给 React 组件引入测试框架是有意的：本阶段是把已验证的行为换个写法，验收标准是
「跟现在一模一样」，而那由手工清单覆盖得更直接。真需要组件测试时再引入不迟。

手工验收清单：

- [ ] 浏览器打开 `http://127.0.0.1:4517`，功能与 3a 的 GUI 完全一致
- [ ] Electron 窗口显示同一个界面
- [ ] 两边同时开着，看到同一个会话，任一边发消息另一边同步
- [ ] Markdown 正确渲染（标题、列表、代码块、粗体）
- [ ] **让模型输出一段 HTML，确认显示为文字而非被执行**
- [ ] 目录选择器能逐层进入并切换项目
- [ ] 中止、权限确认、thinking 折叠、费用显示全部照旧
- [ ] `preload.js` 与 IPC 通道已从仓库删除
- [ ] **`npm install` 后被拦下的安装脚本仍是原来那三个**
- [ ] `node --test` 45 个以上全绿
