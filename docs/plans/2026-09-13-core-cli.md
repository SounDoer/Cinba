# 本机 Core 命令行控制方案

日期：2026-09-13

状态：已实施并通过真实命令行生命周期验证；完整仓库检查见对应提交记录

## 1. 命令

保留裸 `cinba` 启动 TUI，并增加：

```text
cinba core status
cinba core start
cinba core stop
```

- `status` 只读，显示 stopped/running/draining、PID、生命周期、客户端数和是否安全停止。
- `start` 只确保共享本机 Core 可用，不打开 Web 或 TUI。
- `stop` 请求 Core 进入已有的 draining；不直接按 PID 强杀进程。

## 2. 安全边界

`core-manager` 每次启动 Core 时生成随机 control token，保存在 `~/.cinba` 下权限为 `0600` 的独立
文件中，并只通过子进程环境传给 server。server 仅在同时满足以下条件时开放本机控制接口：

- 生命周期为 `on-demand`；
- 启动环境中有 control token；
- 请求携带匹配的 Bearer token。

server 仍只监听 `127.0.0.1`。状态和停止请求由 `core-client` 中的浏览器安全 HTTP 边界完成，
`core-manager` 不绕过共享客户端包直接访问 server。普通健康接口继续保持现有形状，避免影响 deploy。

由 dev、systemd 或其他 checkout 启动的 Core 没有匹配控制文件时，CLI 只报告为 external，不尝试
停止。旧 control 文件不等于进程存活，所有判断仍以实时健康响应为准。

## 3. 调用关系

```text
scripts/cinba.ts
  ├─ cinba [tui] [project] ──► scripts/launch.ts: launchTui()
  └─ cinba core ... ─────────► @cinba/core-manager
                                  │
                                  ▼
                             @cinba/core-client
                                  │ token-protected HTTP
                                  ▼
                             @cinba/server ──► drain controller
```

未来 Desktop 托盘只调用同一组 `inspectLocalCore()`、`ensureLocalCore()` 和 `stopLocalCore()`，不复制
命令行逻辑。
